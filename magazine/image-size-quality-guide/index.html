디지털 생활

사진 용량 줄이기 전에 알아야 할 픽셀·파일 형식·압축 품질

이미지의 가로세로 크기와 저장 형식이 파일 용량과 화질에 각각 어떤 영향을 주는지 실제 예시로 설명합니다.

생활계산소 · 2026년 10월 1일

픽셀 수를 줄이는 것과 압축은 다른 작업입니다

사진 파일이 너무 크다면 먼저 가로세로 픽셀 수를 확인하세요. 4000×3000픽셀 사진은 약 1,200만 개의 픽셀을 표현합니다. 가로와 세로를 각각 절반인 2000×1500픽셀로 줄이면 픽셀 수는 약 300만 개로 4분의 1이 됩니다. 화면에 작게 보여 줄 사진이라면 원본 해상도를 그대로 유지할 필요가 없을 수 있습니다. 다만 픽셀 수가 4분의 1이라고 저장 파일도 정확히 4분의 1이 되는 것은 아닙니다. 사진의 무늬, 저장 형식과 압축 설정이 함께 영향을 주기 때문입니다.

압축 품질은 같은 픽셀 크기의 이미지를 저장할 때 데이터를 얼마나 줄일지 결정합니다. JPEG나 WebP의 손실 압축에서는 품질을 낮추면 파일이 작아질 수 있지만, 글씨와 얇은 선의 경계가 흐려지거나 블록 형태의 흔적이 생길 수 있습니다. 먼저 실제 사용 크기로 줄이고, 그다음 품질을 조금씩 조절해 비교하는 순서가 판단하기 쉽습니다. 브라우저에서 저장 형식과 품질을 지정하는 방식은 Canvas API에서도 제공됩니다.

JPEG, PNG, WebP 중 무엇을 고를까

일반적인 사진은 JPEG나 WebP로 시험해 볼 만합니다. PNG는 로고, 단순한 도형, 선명한 글자나 투명 배경이 필요한 이미지에 적합한 경우가 많습니다. JPEG는 투명 영역을 표현할 수 없으므로 투명 배경이 있는 PNG를 JPEG로 바꾸면 원래의 배경 효과를 보존할 수 없습니다. WebP 역시 내용과 설정에 따라 결과가 다르므로 파일 크기만 보고 형식을 고르지 말고 실제 표시될 브라우저와 사용처에서 열리는지 확인하세요.

예를 들어 온라인 지원서에 2MB 이하 사진이 필요하다면 처음부터 품질을 극단적으로 낮추지 마세요. 제출 화면에서 요구하는 픽셀 규격이 있다면 그 크기에 맞추고, 저장 결과가 제한을 넘을 때 품질을 단계적으로 낮추는 편이 낫습니다. 얼굴 윤곽이나 문서의 작은 글씨가 중요한 파일은 축소 뒤 확대해서 읽을 수 있는지도 확인해야 합니다.

  • 웹 게시용 사진

    실제 화면 너비에 맞춰 픽셀을 줄인 뒤 JPEG와 WebP의 결과를 비교합니다.

  • 투명 로고

    배경 투명도가 유지되는 형식인지 먼저 확인합니다.

  • 증빙·문서 이미지

    용량보다 작은 글씨와 세부 정보의 가독성을 우선 확인합니다.

원본을 보관하고 결과를 직접 확인하세요

이미지를 반복해서 손실 압축 형식으로 저장하면 이전 저장 단계에서 사라진 세부 정보를 되돌릴 수 없습니다. 원본은 별도로 보관하고 변환본에 다른 이름을 붙이는 편이 안전합니다. 공유하거나 제출하기 전에는 결과 파일의 크기뿐 아니라 회전 방향, 투명도, 가로세로 비율과 텍스트 가독성을 확인하세요. 이미지 도구는 브라우저에서 변환을 돕지만 특정 사이트의 업로드 규격이나 인쇄 품질을 자동으로 보증하지 않습니다.

목적별로 크기를 결정하는 실전 순서

먼저 이미지가 놓일 최종 위치를 확인합니다. 작은 게시글 카드에만 쓸 이미지와 확대해서 읽어야 하는 증빙 사진은 필요한 픽셀이 다릅니다. 원본이 4000×3000픽셀인데 목표가 1200×900픽셀이라면 가로와 세로를 같은 비율로 줄여 형태가 찌그러지지 않게 합니다. 1200×900은 약 108만 픽셀로 원본 1200만 픽셀의 약 9%이지만, 파일 크기까지 9%가 된다는 뜻은 아닙니다.

파일 형식은 이미지 성격으로 고릅니다. 풍경 사진은 JPEG와 WebP 변환본을 실제 크기로 열어 질감을 비교합니다. 글자가 빽빽한 캡처나 투명한 로고는 PNG 또는 적절한 WebP 결과를 눈으로 확인하세요. WebP는 손실·무손실과 투명도를 지원하지만, 제출처가 특정 형식만 받는다면 그 규격이 우선입니다. 형식을 바꾸기만 해도 항상 작아지는 것은 아니므로 결과 용량을 확인해야 합니다.

용량 제한을 맞추는 두 가지 예시

첫 번째로 4000×3000픽셀 6MB 사진을 2MB 이하로 제출해야 한다고 가정해 보겠습니다. 제출처가 1600×1200픽셀을 허용하면 먼저 그 크기로 축소하고 JPEG 품질 0.85와 0.75 결과를 각각 비교합니다. 예를 들어 결과가 1.9MB와 1.3MB라면 둘 다 조건을 만족하지만, 얼굴이나 글씨가 더 잘 보이는 1.9MB 파일을 선택할 수 있습니다. 이 숫자는 예시이며 사진 내용과 브라우저 인코더에 따라 실제 용량은 달라집니다.

두 번째로 1200×600픽셀 투명 로고가 900KB라고 가정합니다. 600×300픽셀로 축소할 수 있다면 먼저 출력 크기가 충분한지 확인하고 PNG와 투명 WebP 결과를 비교합니다. 로고를 JPEG로 바꾸면 투명 배경이 유지되지 않으므로 파일이 작아져도 요구사항을 충족하지 못할 수 있습니다. 선이 번지거나 색이 변하면 축소 폭이나 형식을 다시 조정하세요.

파일을 저장한 뒤 확인할 체크리스트

다운로드한 파일을 실제로 다시 열어 가로세로 픽셀, 확장자, 용량을 확인하세요. 원본과 결과를 나란히 두고 작은 문자, 얼굴 윤곽, 색 경계, 투명 배경을 비교합니다. 사진에 포함된 위치 정보나 촬영 기기 정보처럼 공개하고 싶지 않은 메타데이터가 있다면 별도 확인이 필요합니다. 화면 미리보기만으로 메타데이터 제거 여부를 단정할 수 없습니다.

브라우저 Canvas의 품질 매개변수는 JPEG·WebP 같은 손실 압축 형식에 적용되며 PNG 결과에는 같은 방식으로 작동하지 않습니다. 일부 환경에서는 요청한 형식으로 저장하지 못할 수도 있으므로 저장 후 파일 형식을 다시 확인하는 것이 좋습니다.

자주 묻는 질문

가로세로를 절반으로 줄이면 용량도 절반인가요?

아닙니다. 픽셀 수는 4분의 1이 되지만 실제 파일 크기는 사진 내용, 형식, 압축 품질에 따라 달라집니다.

품질을 100%로 두면 원본과 같나요?

손실 형식으로 다시 저장하는 과정에서 원본과 동일한 데이터가 보장되지 않습니다. 원본을 별도로 보관하세요.

PNG 품질 슬라이더가 효과가 적은 이유는?

브라우저 Canvas의 품질 값은 주로 JPEG·WebP 같은 손실 압축 인코딩에 적용됩니다. PNG에서는 크기 조절이나 다른 형식 선택이 더 의미 있을 수 있습니다.

문서 사진은 무엇을 우선 확인하나요?

업로드 제한을 맞춘 다음 확대해서 작은 글씨와 서명·숫자를 읽을 수 있는지 확인하세요. 가장 작은 파일이 항상 적합한 결과는 아닙니다.
