비밀번호는 얼마나 길어야 할까? 생성부터 계정별 보관까지

길고 무작위인 비밀번호를 만들고 계정마다 다르게 관리하는 이유, 생성 뒤 확인할 사항을 정리했습니다.

생활계산소 · 2026년 10월 2일

길이와 예측 가능성이 중요한 이유

비밀번호는 길이만 늘리면 무조건 안전해지는 숫자 게임이 아닙니다. 이름, 생일, 흔한 문장을 조금 바꾼 값은 길어 보여도 추측될 수 있습니다. 반대로 암호학적으로 강한 난수로 만든 긴 문자열은 사람이 떠올린 규칙을 재현하기 어렵습니다. 같은 문자 집합에서 각 자리를 독립적으로 뽑는 단순 모델이라면 가능한 조합 수는 문자 종류 수를 비밀번호 길이만큼 거듭제곱한 값입니다. 실제 생성 도구는 선택한 문자 종류를 반드시 포함하는 등의 조건이 있어 이 식을 보안 보증치로 해석해서는 안 됩니다.

미국 NIST의 디지털 신원 지침은 단일 인증 수단으로 쓰는 비밀번호에 최소 15자를 요구하는 검증자 기준을 제시합니다. 이것이 모든 사이트의 가입 화면이 15자를 허용하거나 사용자가 정확히 15자만 설정하면 된다는 뜻은 아닙니다. 사이트별 최대 길이와 허용 문자를 확인하고, 가능한 범위에서 충분히 길고 무작위인 값을 선택하세요.

생성한 뒤에는 계정마다 다르게 저장합니다

하나의 비밀번호를 여러 사이트에서 재사용하면 한 곳에서 유출됐을 때 다른 계정에도 같은 값이 시도될 수 있습니다. 생성기에서 새 값을 만들고 해당 사이트의 비밀번호 관리자 항목에 저장하세요. 외우기 어렵다고 메모 앱의 일반 문서나 메신저 대화에 그대로 남겨 두면 생성 과정이 안전해도 보관 과정이 취약해집니다. 생성기가 값을 서버로 보내지 않더라도 복사한 문자열은 기기의 클립보드나 화면 공유에 노출될 수 있으므로 공유 기기에서는 특히 주의해야 합니다.

예를 들어 쇼핑몰, 이메일, 금융 서비스를 각각 이용한다면 세 계정에 서로 다른 비밀번호를 만듭니다. 나중에 한 서비스를 해지하거나 비밀번호를 바꿀 때 다른 두 서비스의 값을 함께 바꿀 필요가 없게 됩니다. 중요한 계정에는 서비스가 제공하는 다중 인증을 추가하고 복구 이메일과 복구 코드도 점검하세요. 비밀번호는 피싱이나 악성 프로그램을 완전히 막아 주지 못하므로 로그인 주소와 기기 상태를 확인하는 습관도 필요합니다.

  • 생성 전

    가입 화면의 길이·문자 규칙을 확인합니다.

  • 생성 후

    계정마다 다른 값을 안전한 비밀번호 관리자에 저장합니다.

  • 정기 점검

    유출 알림과 다중 인증·복구 수단을 확인하고 필요한 계정만 변경합니다.

‘강도’ 숫자만 믿지 않아야 하는 이유

비밀번호 생성기가 보여 주는 엔트로피나 강도 표시는 설정을 비교하는 참고값입니다. 실제 계정의 안전성은 사이트의 로그인 시도 제한, 비밀번호 저장 방식, 다중 인증, 사용자의 피싱 대응에도 달려 있습니다. 무작위 문자열을 만들었다면 생성 결과를 게시하거나 지인에게 전달하지 말고, 비밀번호 관리자에서 해당 계정의 주소와 함께 보관하세요. 이 사이트의 생성 도구는 사용자가 만든 값을 다시 불러오는 기능을 제공하지 않습니다.

길이와 문자 종류를 실제로 선택하는 방법

비밀번호 생성기의 길이 옵션은 가입하려는 사이트가 허용하는 범위를 먼저 확인한 뒤 정합니다. 예를 들어 16자 무작위 문자열을 만든 후 가입 화면이 특수문자를 거부한다면 허용 문자 집합으로 다시 생성하세요. 특수문자 한 글자를 손으로 바꾸거나 사이트 이름을 뒤에 붙이는 방식보다 생성기에서 조건에 맞는 전체 문자열을 새로 뽑는 편이 실수를 줄입니다.

같은 문자 집합에서 독립적으로 뽑는 이상적인 모델이라면 길이를 늘릴수록 가능한 조합 수가 증가합니다. 하지만 이론상 조합 수와 실제 계정의 안전성은 같지 않습니다. 사이트에 로그인 시도 제한이 있는지, 비밀번호가 유출됐는지, 피싱 페이지에 입력했는지가 함께 중요합니다. NIST는 서비스 운영자에게 흔한 비밀번호 차단, 비밀번호 관리자 허용, 정기적 강제 변경 금지 등의 기준을 제시합니다. 사용자는 이 기준을 사이트별 실제 정책과 구분해 참고해야 합니다.

계정 세 개를 정리하는 구체적인 예

이메일·쇼핑몰·동영상 서비스에 같은 10자리 암호를 쓰고 있다고 가정해 보겠습니다. 우선 이메일 계정부터 고유한 긴 무작위 값으로 바꾸고 비밀번호 관리자에 저장한 뒤 다중 인증을 켭니다. 그다음 쇼핑몰과 동영상 서비스에도 서로 다른 값을 새로 생성합니다. 예를 들어 세 계정 모두 18자리 문자열을 사용하더라도 세 값은 서로 달라야 합니다. 한 곳의 유출이 다른 계정으로 이어지는 재사용 위험을 줄이는 것이 목적입니다.

비밀번호 관리자에 저장할 때에는 계정 주소를 확인하고 동기화·복구 수단을 점검하세요. 기기를 바꾸거나 관리자의 잠금 해제 수단을 잃었을 때 계정에 접근할 수 있는지도 미리 확인해야 합니다. 복구 코드를 제공하는 서비스라면 비밀번호와 같은 노출 위치에 무심코 저장하지 말고 별도 안전한 장소를 정하세요.

유출이 의심될 때의 대응 순서

피싱 사이트에 암호를 입력했거나 유출 알림을 받았다면 해당 서비스의 공식 주소에서 비밀번호를 즉시 변경하고 활성 세션을 확인하세요. 같은 암호를 다른 계정에도 썼다면 재사용한 계정부터 각각 다른 값으로 변경해야 합니다. 다중 인증이 가능한 계정은 활성화하고 최근 로그인 기록·복구 주소도 점검합니다.

무작위 비밀번호를 주기적으로 모두 교체하는 것보다 유출·피싱·기기 분실 등 실제 문제가 발생했을 때 정확히 대응하는 일이 중요합니다. NIST 역시 증거 없이 정기적 변경을 강제하는 운영 정책을 권하지 않습니다. 단, 회사·학교 등 사용 중인 서비스가 별도 정책을 요구한다면 그 정책도 확인하세요.

자주 묻는 질문

15자면 무조건 안전한가요?

아닙니다. NIST의 15자 기준은 단일 인증 비밀번호를 받는 서비스 운영자에 대한 최소 길이 요구사항입니다. 흔한 문장이나 유출된 값은 길어도 위험할 수 있습니다.

특수문자를 반드시 섞어야 하나요?

사이트의 가입 규칙을 먼저 따르세요. NIST는 검증자에게 문자 종류를 의무적으로 섞게 하는 규칙을 요구하지 말라고 권고합니다. 길고 무작위이며 계정별로 고유한 값이 핵심입니다.

비밀번호를 정기적으로 바꿔야 하나요?

유출 증거가 없을 때 일괄적으로 자주 교체하는 것보다 재사용을 피하고 다중 인증을 설정하는 것이 중요합니다. 유출이나 피싱이 의심되면 즉시 바꾸세요.

생성한 값을 어디에 보관하나요?

신뢰할 수 있는 비밀번호 관리자에 계정 주소와 함께 보관하고, 관리자 접근·복구 수단을 점검하세요. 채팅방이나 평문 메모에 남기지 마세요.
