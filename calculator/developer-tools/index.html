    JSON 정리·Base64·URL 변환 원리

    이 개발자 도구는 복사한 데이터나 문자열을 별도 프로그램 없이 확인해야 할 때 사용하는 브라우저 기반 유틸리티입니다. 입력한 원문과 변환 결과는 생활계산소 서버나 데이터베이스로 전송되지 않으며 현재 탭의 JavaScript에서만 처리됩니다. localStorage에는 마지막으로 선택한 작업, JSON 들여쓰기 폭, URL 처리 범위만 사용자 설정으로 저장합니다. API 응답, 토큰, 개인정보처럼 민감한 문자열은 페이지를 닫기 전에 결과를 필요한 곳에 옮기고, 화면 공유나 클립보드 기록을 남기는 다른 프로그램이 실행 중인지도 확인하세요.

    JSON 정리(Beautify)는 JSON.parse로 문법을 해석한 다음 JSON.stringify로 다시 출력합니다. 중괄호와 대괄호의 계층에 따라 공백 2칸, 4칸 또는 탭을 넣기 때문에 한 줄로 긴 응답도 구조를 읽기 쉬워집니다. JSON 압축(Minify)은 같은 값을 불필요한 줄바꿈과 들여쓰기 없이 한 줄로 만듭니다. 두 작업 모두 작은따옴표, 주석, 마지막 쉼표를 허용하지 않는 표준 JSON 문법을 따릅니다. 객체 안에 같은 키가 반복되면 JavaScript가 마지막 값을 남길 수 있으므로 중복 키가 의심되는 원본은 변환 전에도 확인해야 합니다. 정리 기능은 데이터의 의미나 키 순서를 검증하는 스키마 검사기가 아니라 문법 확인과 표시 형식 변경 도구입니다.

    Base64 인코딩은 문자열을 UTF-8 바이트로 바꾼 뒤 6비트 단위의 영문·숫자 기호 문자열로 표현합니다. 따라서 한글과 일반 이모지도 브라우저의 UTF-8 변환을 거쳐 처리됩니다. Base64는 데이터를 암호화하거나 비밀로 만드는 기술이 아니며 누구나 다시 디코딩할 수 있습니다. 이메일 본문, data URI, 테스트 데이터처럼 이진 데이터를 텍스트 환경에 옮길 때 쓰지만 결과 길이는 대체로 원본 바이트보다 약 33% 늘어납니다. 디코딩 시 공백과 줄바꿈은 제거하고 형식을 확인한 뒤 UTF-8 텍스트로 해석하며, 다른 문자 인코딩으로 만든 Base64는 올바른 문장으로 복원되지 않을 수 있습니다.

    URL 인코딩은 공백, 한글과 예약 문자를 퍼센트 기호와 UTF-8 16진수로 바꿉니다. ‘일부 문자열’은 encodeURIComponent와 decodeURIComponent를 사용해 검색어, 쿼리 파라미터 값처럼 주소 구성 요소 하나를 처리합니다. 이 방식에서는 &, =, ?도 데이터로 보고 인코딩합니다. ‘전체 URL 구조 유지’는 encodeURI와 decodeURI를 사용해 https://, 경로 구분자, 쿼리 구분 기호를 남기므로 완성된 주소 전체에 적합합니다. 이미 인코딩된 값을 다시 인코딩하면 %가 %25로 바뀌는 이중 인코딩이 생길 수 있으며, 잘못된 % 조합은 디코딩 오류가 납니다.

    기능별 사용 방법

    JSON Beautify와 압축

    JSON을 붙여 넣고 들여쓰기 폭을 선택해 실행합니다. 정리는 계층을 여러 줄로 보여주고 압축은 공백 없는 한 줄로 만듭니다. 오류가 표시되면 따옴표, 쉼표와 괄호의 짝을 먼저 확인하세요.

    UTF-8 Base64 변환

    한글·영문 원문을 인코딩하거나 Base64 문자열을 디코딩합니다. 결과는 복사할 수 있지만 보안 기능은 아니므로 비밀번호와 인증 키를 공개 채널에 공유하면 안 됩니다.

    URL 문자열 변환

    검색어 하나는 ‘일부 문자열’, https://로 시작하는 완성 주소는 ‘전체 URL 구조 유지’를 선택합니다. 변환 후 목적 서비스가 요구하는 인코딩 범위와 일치하는지 확인하세요.

    개발자 도구 사용 예시

    API JSON 응답 정리

    {"name":"Askumi","active":true}를 공백 2칸으로 정리하면 키와 값이 여러 줄로 배치되어 객체 구조를 빠르게 읽을 수 있습니다.

    한글 Base64 인코딩

    ‘생활계산소’를 UTF-8 Base64로 인코딩하면 7IOd7Zmc6rOE7IKw7IaM이 됩니다. 같은 값을 디코딩하면 원문으로 돌아옵니다.

    검색어 URL 인코딩

    ‘여행 경비’를 일부 문자열로 인코딩하면 공백과 한글이 퍼센트 표기로 바뀝니다. 검색 주소의 q 값처럼 한 파라미터에 넣을 때 사용할 수 있습니다.

    JSON·Base64·URL 도구 FAQ

    입력한 JSON이나 문자열이 서버에 저장되나요?

    아니요. 원문과 결과는 현재 브라우저에서만 처리하며 저장하거나 전송하지 않습니다. 작업 종류 같은 화면 설정만 localStorage에 저장합니다.

    JSON 정리 중 오류가 나는 이유는 무엇인가요?

    표준 JSON은 키와 문자열에 큰따옴표를 사용하고 주석이나 마지막 쉼표를 허용하지 않습니다. 괄호의 짝과 누락된 쉼표도 확인하세요.

    Base64로 바꾸면 내용이 암호화되나요?

    아니요. Base64는 바이트를 문자로 표현하는 인코딩이며 비밀을 보호하지 않습니다. 민감한 데이터 보호에는 검증된 암호화 방식을 사용해야 합니다.

    한글과 이모지도 Base64로 변환할 수 있나요?

    예. 이 도구는 먼저 UTF-8 바이트로 변환하므로 한글과 일반 이모지를 처리합니다. 다른 인코딩으로 만들어진 값은 디코딩되지 않을 수 있습니다.

    URL 전체와 일부 문자열 중 무엇을 골라야 하나요?

    완성된 URL은 전체 URL 구조 유지, 검색어와 쿼리값 하나는 일부 문자열을 권장합니다. 일부 문자열 방식은 ?, &, = 같은 구분 기호도 인코딩합니다.

    %가 포함된 URL을 디코딩할 때 오류가 납니다.

    % 뒤에는 두 자리 16진수가 있어야 합니다. 이미 일부만 디코딩된 값이나 잘린 문자열에는 잘못된 퍼센트 조합이 있을 수 있습니다.

    아주 긴 데이터도 처리할 수 있나요?

    모바일 성능과 탭 멈춤을 줄이기 위해 500,000자로 제한합니다. 큰 로그와 데이터 파일은 전용 로컬 편집기에서 나누어 확인하세요.
